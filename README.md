# seoul-apt

국토교통부 실거래가 데이터로 서울 아파트 시세를 살펴보는 **로컬 전용** 웹 앱.
Next.js 화면과 SQLite 데이터가 실제로 붙어 있는, 작지만 동작하는 풀스택 학습 프로젝트다.

> 배포하지 않는다. `npm run dev` 로 내 PC에서 뜨는 것까지가 목표다.

## 스택

Next.js 16 (App Router) · React 19 · TypeScript · Tailwind CSS v4 · SQLite(better-sqlite3) · Recharts

ORM 없이 생 SQL을 쓰고, 화면은 서버 컴포넌트가 기본이다.
클라이언트 컴포넌트는 필터 바 하나뿐이다.

## 시작하기

```bash
npm install
npm run seed     # db/seed/*.csv → data/seoul_apt.db (약 7만 건, 1초 내외)
npm run dev      # http://localhost:3000
```

| 명령 | 하는 일 |
| --- | --- |
| `npm run dev` | 개발 서버 |
| `npm run seed` | CSV를 SQLite에 적재 |
| `npm run db-reset` | DB를 지우고 다시 적재 |
| `npm run db-stats` | 적재 결과 확인 (자치구별 평당가 중앙값) |
| `npm run build` | 타입·빌드 오류 확인용 (배포용이 아니다) |
| `npm run lint` | ESLint |

`start` 스크립트는 의도적으로 없다. 배포하지 않기 때문이다.

## 데이터

[국토교통부 실거래가 공개시스템](https://rt.molit.go.kr/)에서 **한 번 수동으로 내려받은 CSV**가
`db/seed/`에 들어 있다. 앱은 실행 중에 외부를 호출하지 않으므로 오프라인에서도 동작한다.

- 범위: 서울 전체 아파트 매매, 계약일 **2025-09-02 ~ 2026-09-01**
- 원본 75,055건 → 해제(취소) 2,444건 제외 → **유효 72,611건 / 단지 5,925개 / 25개 구 / 317개 동**

`npm run db-stats` 출력 일부:

```
complexes 5,925
trades    72,611
기간      2025-09-02 ~ 2026-08-31

자치구별 평당가 중앙값:
  강남구    2741건   11,131만원/평
  서초구    2192건    7,928만원/평
  용산구    1126건    7,666만원/평
  ...
  도봉구    2601건    2,705만원/평
```

### 데이터를 다루며 알게 된 것

원본 CSV를 전량 파싱해 확인한 사실들이고, 코드가 이 전제 위에 서 있다.

- **인코딩이 CP949**다. 앞 15줄은 안내문이고 `첫 셀이 'NO'`인 줄이 헤더다.
- 값 안에 콤마가 있어서(`"46,000"`) **따옴표를 인식하는 파서가 필요**하다. `split(',')`으로는 깨진다.
- **해제(취소)된 계약이 3.26% 섞여 있다.** 걸러내지 않으면 통계가 틀어진다.
- 단지 식별 키는 `(구, 동, 번지, 단지명)`이다. **건축년도를 키에 넣으면 안 된다** —
  같은 단지가 1975/1976/1977로 갈리는 경우가 56건 있다.
- 최고가가 250억(나인원한남)이라 **평균은 이상치에 끌려간다.** 중앙값을 쓴다.
- **단지의 26%는 거래가 1건뿐**이다. 시세 추이를 항상 그릴 수 있다고 가정하면 안 된다.
- 가장 최근 달은 신고 지연으로 건수가 미완성이다(신고 기한 30일).
- CSV의 `동` 컬럼은 법정동이 아니라 아파트 동번호이고 31%가 비어 있다.

기간을 넓히려면 같은 조건으로 CSV를 더 받아 `db/seed/`에 넣고 `npm run db-reset` 하면 된다
(시도별 다운로드는 1년 단위가 최대다).

## 구조

```
db/schema.sql          스키마 단일 진실 소스 (마이그레이션 도구 없음)
db/seed/*.csv          국토부 원본 CSV — 읽기 전용
scripts/seed.mjs       CP949 디코딩 → CSV 파싱 → 정규화 → 단일 트랜잭션 적재
scripts/stats.mjs      적재 결과 확인
src/lib/db.ts          커넥션 1개, 연결 시 스키마 멱등 적용
src/lib/queries.ts     앱의 모든 SQL이 여기 있다
src/lib/format.ts      만원 → 억, ㎡ → 평
src/app/               페이지 (서버 컴포넌트)
src/components/        UI 조각
```

테이블은 둘뿐이다. 평당가는 매번 다시 계산하지 않도록 **생성 컬럼**으로 고정했다.

```sql
complexes (id, gu, dong, jibun, name, built_year)
trades    (id, complex_id, deal_date, price_manwon, area_m2, floor,
           price_per_pyeong GENERATED ALWAYS AS (price_manwon / (area_m2 / 3.3058)) STORED)
```

## 진행 상황

v1은 기능 **2개**에서 멈춘다. 범위를 늘리지 않는 것 자체가 이 프로젝트의 연습 과제다.

- [x] CSV → SQLite 적재 (72,611건)
- [x] `/` 실거래 목록 — 자치구 필터 · 페이지네이션
- [x] `/complex/[id]` 단지 상세 — 통계와 거래 이력
- [x] 표 헤더 클릭 정렬 (면적·층·계약일·금액·평당가, 오름/내림)
- [x] 월별 시세 흐름 차트 (목록: 구 단위 / 상세: 단지 단위)

**v2 백로그**: 법정동 2단 필터, 면적대 필터, 구별 평당가 랭킹, 단지 비교.

의도적으로 넣지 않은 것: 로그인, 결제, 외부 API 연동, 배포, 지도, 쓰기 기능,
ORM, 상태 관리 라이브러리.

### 차트를 읽을 때

선은 월별 **중앙** 평당가이고, 막대는 그 달의 **거래건수**다. 둘을 같이 그린 이유가 있다.
종로구 2025-11 은 24건뿐인데 중앙값이 3,283만원/평로 앞뒤 달(4,522 / 4,230)보다 뚝 떨어진다.
실제 시세 하락이 아니라 표본이 작아서 생긴 흔들림이다. 막대가 짧은 달의 점은 믿지 말아야 한다.
마지막 달은 신고 기한(계약 후 30일)이 남아 건수가 항상 덜 차 있다.

## 참고

본 데이터는 국토교통부 실거래가 공개시스템에서 제공하는 정보로, **법적 효력이 없으며 참고용**이다.
